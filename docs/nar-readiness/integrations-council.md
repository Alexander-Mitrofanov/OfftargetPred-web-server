# Integration and architecture council: OfftargetPred

**Assessment date: 19 September 2026. Recommendations only; no production changes.**

## Recommendation

Build a coherent **sequence-model evaluation and experimental prioritization workflow** around CRISPert-small. The useful unit is a guide, its explicitly bounded candidate set, separate model rankings, genomic context, experimental evidence, and a reproducible shortlist. Adding a directory of other predictors would not establish a contribution.

The smallest submission bundle is: documented independent evaluation; k1/k2/k3 rank comparison; locally pinned gene/exon context; an evidence-aware shortlist and curated interactive example; and BED/JSON plus a working API client. CFD can remain an audited offline evaluation baseline; live computation is optional. Embedded IGV.js is optional. Model disagreement is descriptive, not calibrated uncertainty.

NAR excludes primarily third-party aggregators and expects useful rich output, private submissions, independent predictive validation, and maintenance for at least five years. Demonstrate the added biological or usability value of the integrated workflow. [NAR Web Server instructions](https://academic.oup.com/nar/pages/Submission_Webserver)

### What would make this distinctive?

CRISPOR already offers guide ranking, CFD/MIT scores, genomic context and primer design; CHOPCHOP covers multiple targeting workflows. These features are comparators and interoperability targets, not new scientific claims. [CRISPOR manual](https://github.com/maximilianh/crisporWebsite/blob/master/manual/manual.md), [CHOPCHOP v3 paper](https://academic.oup.com/nar/article/47/W1/W171/5491735)

Test the specific contribution: on documented guide-disjoint evaluation data, does CRISPert ranking recover additional experimentally observed sites at a fixed shortlist budget, or reduce effort in producing a defensible shortlist? Report per-guide recall at 10/50/100, precision at a fixed budget, and end-to-end nomination recall alongside ranking performance on the same candidate universe. Show failures and guides where a baseline wins. A faster workflow is a separate claim requiring a small observed user study, not inference from having fewer clicks.

The science council found one exact guide and 981 sequence pairs shared between the supplied full K562 and T-cell files. This is **cross-cell sequence overlap**; the actual training split is not recoverable from those files alone. Resolve training and model-selection provenance before calling this independent validation. The separate 12-guide K562 file appears guide-disjoint in the council audit, but its assay provenance, negative construction and selection exposure still need confirmation. An illustrative UI demo can proceed with accurate labels; it must not masquerade as independent performance evidence.

## Current implementation: what is already sound, and where integrations attach

Sources inspected: [README](../../README.md), [model card](../model-card.md), [API](../API.md), [deployment](../deployment.md), [launch evidence](../validation/README.md), `backend/offtargetpred/{api,search,worker,inference,jobs,config}.py`, `frontend/src/App.tsx`, and `pyproject.toml`.

- The three immutable sequence-only checkpoints take **two aligned 23 nt sequences including the actual PAM**. There is no gap representation, CasKAS, epigenetic input, retraining, calibrated cleavage probability or valid automatic ensemble.
- Pair input supports several existing column aliases and preserves row identity; coordinates are not guaranteed. Gene annotation and browser export therefore apply to genome-search results or to explicitly supplied, verified coordinates, not automatically to every pair.
- Genome search is pinned to Cas-OFFinder 2.4.1 and Ensembl release 115 GRCh38 primary assembly, NGG, 0–4 protospacer substitutions, at most ten guides. Zero-mismatch sites are retained. A unique intended target is not inferred. Results use 0-based half-open genomic intervals with PAM and guide-oriented sequences.
- The private asynchronous API, bearer capabilities, cancellation/deletion, 24-hour retention, result metadata, model hashes and reference provenance already exist. The public Pages frontend and Funnel API passed normal-DNS launch checks. This memo does not treat Funnel as unavailable.
- Current capacity is one running job, ten queued jobs, at most 10,000 supplied pairs or 50,000 genome candidates, and a 900-second whole-job timeout. Overflow fails explicitly; this is preferable to presenting a truncated search as complete.
- `worker.py` creates a new inference engine per job; `search.py` hashes the reference on each search; `api.py` reads and sorts the full JSON result for each page request. These are **profiling targets**, not established bottlenecks. Existing launch evidence covers a small genome query, not the complete allowed workload envelope.

## Prioritized integration matrix

Effort is an estimate for one experienced engineer with scientific review, including fixtures, UI, documentation and meaningful acceptance checks. It excludes permission delays, data acquisition, new experiments and ongoing maintenance. Work overlaps, so ranges should not simply be summed. **Local** means the OfftargetPred service or the user's browser; **link** means a deliberate external browser action; **API** means an actually documented interface, not reverse-engineered form submission.

### Research required before a user-facing claim

**Search coverage has two different expansion paths.** More than four mismatches or additional three-base PAM classes can still produce ungapped 23-mers accepted by the existing representation; this does not inherently require a new model. It does require mismatch/PAM-stratified validation, candidate-volume and runtime measurements, provenance and revised limits. Bulges, different spacer lengths and other nuclease geometries are different: they do not fit the current input contract. The root audit found only 91 of 188 positive pairs in the supplied full K562 file satisfy the current NGG/≤4-mismatch necessary sequence filters. That is a filter-eligibility result, not measured genome-search recall, and motivates an explicit scope-sensitivity experiment.

## Integration contracts and licensing gates

### Genome context

Use local, release-pinned annotations by default. Ensembl has a documented overlap API, and UCSC has documented sequence/track endpoints; those are suitable for sparse deliberate lookups or controlled reference preparation. They should not be a live per-hit dependency for a 50,000-hit job. UCSC itself recommends bulk alternatives and restraint on request frequency. [UCSC REST API](https://genome.ucsc.edu/goldenPath/help/api.html)

Do not equate `hg38` and a specific Ensembl primary-assembly file without a contig/reference mapping check. For UCSC-style aliases, maintain an explicit mapping for primary chromosomes, mitochondria and unplaced/unlocalized contigs; do not simply prepend `chr` everywhere. Annotations need their own manifests and licensing checks. UCSC notes that some third-party datasets have redistribution restrictions, despite broad access to its own resources. [UCSC licensing](https://genome.ucsc.edu/license/), [download FAQ](https://genome.ucsc.edu/FAQ/FAQdownloads)

No CasKAS, chromatin accessibility, epigenetic features or corresponding browser overlays are proposed. Gene structure supplies interpretation only, and must not be fed back into the sequence models or sold as a validated consequence score.

### Concrete licensing traps

- **CRISPOR:** local source is under special terms, not a blanket permissive license; bundled components have their own licenses. Its LICENSE text also says the hosted website stores submitted sequence and genome identifiers for at least 24 months. That is incompatible with silently forwarding data under OfftargetPred's 24-hour expectation. The text has differing academic/nonprofit wording across sections; resolve the exact intended use before reusing source. File conversion requires no assumption of a hosted API. [CRISPOR license](https://raw.githubusercontent.com/maximilianh/crisporWebsite/master/LICENSE.txt)
- **CFD/MIT:** a method citation is not a code/data redistribution license. Record exact algorithm, implementation revision and parameter origin, including PAM treatment and numeric scale. `crisprScore` is a promising auditable reference, but package-level licensing does not automatically settle every upstream artifact. [crisprScore license section](https://github.com/crisprVerse/crisprScore#license)
- **Cas-OFFinder:** its license is new BSD except `dirent.h`; check the pinned revision and bundled files for distribution. Scientific compatibility remains a separate gate. [Cas-OFFinder license](https://raw.githubusercontent.com/snugel/cas-offinder/master/LICENSE)
- **CRISPRitz:** the current license file describes academic AGPL use and a separate for-profit license. Resolve applicability to the intended public service and preserve required notices/source obligations before adoption. [CRISPRitz license](https://raw.githubusercontent.com/pinellolab/CRISPRitz/master/LICENSE)
- **CRISPRme:** the retrieved README says MGBOA 1.0 academic/noncommercial, whereas the retrieved LICENSE says academic AGPL plus commercial licensing. The repository is moving to CRISPRme+. This discrepancy may reflect changing upstream versions/caches; it is a release-pinning and clarification gate, not a basis to declare either license universally applicable. [Repository](https://github.com/pinellolab/CRISPRme), [retrieved LICENSE](https://github.com/pinellolab/CRISPRme/blob/main/LICENSE)
- **CHOPCHOP:** public local code/CLI is described in its paper, but this review did not establish a supported hosted submission API or settle current source/dependency licensing. Keep a first integration to verified file formats and deliberate links. [CHOPCHOP paper](https://academic.oup.com/nar/article/47/W1/W171/5491735)
- **OfftargetPred itself:** source and checkpoint distribution rights must be explicit before claiming an installable public CLI/container or bundling models for Galaxy. The root council's missing LICENSE/CITATION finding is an immediate prerequisite, not evidence that upstream model permission has already been granted.

These are engineering release gates, not a legal opinion. Public URLs above were consulted on the assessment date; mutable branches must be replaced with immutable revisions in an implementation manifest.

## Privacy architecture for every integration

1. Submitted DNA, assay evidence and private-job capabilities stay within the authorized service. Avoid automatic remote enrichment or predictor submission.
2. Browser links require a deliberate action and explain the external destination; coordinate-only links still disclose a locus. Do not prefetch them. Never place bearer tokens or sequence tables in external URLs.
3. Bundle IGV.js locally and define reference/annotation hosts explicitly. A remote reference request can reveal the inspected genomic window even without sending a guide sequence. Avoid remote defaults, public track hubs for private results, analytics and accidental credential propagation.
4. No public endpoint is needed for a private BED download. Authenticated fetch into an in-memory/browser-local track keeps the current private-job authorization model.
5. Extend deletion/expiry to annotation caches tied to jobs, imported evidence and any newly generated artifacts. A permanent reference index can be shared; a cache of user guide searches should not silently outlive retention.
6. Keep ephemeral user data out of archival model/reference backups. A downloadable result bundle is user-controlled and must omit access tokens.

## Performance and five-year reliability: feasible gaps, not requests to change operations now

The current GPU setup, immutable model checks, bounded search, isolated per-job process and private queue are useful foundations. Keep them while collecting evidence. Do not replace the isolated process with a resident inference service solely to save model loading time: memory isolation, cancellation and restart behavior would change. Do not remove per-search reference verification without an equivalent integrity strategy for an immutable, read-only reference and evidence that hashing materially affects latency.

The next capacity report should include cold/warm latency, queue delay, candidate counts, p50/p95 where there are enough repeats, CPU fallback behavior where supported, V100 memory, disk pressure and result-table/export responsiveness. Search at four mismatches and repetitive guides is the critical stress case. Adding IGV/annotations must not make inference depend on another public site's availability. Honor current all-or-fail candidate semantics.

Retain an isolated restoration checklist and recovery evidence for source, exact weights, reference, environment and golden predictions. API and frontend compatibility should be versioned separately so a frontend upgrade cannot misread an older worker's schema. Test a restore rather than merely list backup paths. Keep privacy expiry testable across restarts and long jobs.

The launch record already demonstrates public DNS/HTTPS and reboot recovery. Outstanding matters include unsynchronized NTP, the recorded Tailscale key expiry, no demonstrated full restore, and no evidenced five-year institutional allocation/maintainer commitment. A replacement hostname alone cannot create a public route to a private 172.16.x de.NBI address; gateway/ingress design needs the host's permitted network route. None of these operational changes were executed in this council review.

## Council discussion and sequencing

**Agreement with science council:** provenance repair precedes adding predictors. An independent evaluation needs guide-disjoint data and model/tuning provenance; a fresh locked external assay is preferable when available. Report nomination recall separately from score ranking. Disagreement between three related k-mer models must never be converted to an uncertainty interval.

**Agreement with usability council after cross-review:** a curated interactive result, explicit PAM/locus resolution, gene context and an editable shortlist improve an actual laboratory decision. Drop embedded IGV first if time is limited: coordinate-correct links plus BED already support locus inspection. Drop live CFD/MIT next; independent offline comparison remains valuable. A pair-scoring workflow remains useful without knowing a locus.

The shortlist must retain immutable IDs/`row_index`, exact reference/model/search scope, every selected model's score and rank, optional user notes, and a clearly labelled selected-row count. Label full versus selected exports. Exclude an intended locus only after explicit user identification. The curated example should contain real observed and not-detected labels plus a difficult case and cohort provenance; do not fabricate diverse-looking scores. The 20 nt resolver must expose all exact matches, actual PAMs, orientation and ambiguity before scoring.

**Two especially tempting exclusions:** do not add a bulge toggle that promises CRISPert scores for gapped sites; do not open personalized variant upload merely because an upstream enumerator accepts VCF. The former requires a compatible model and evidence, the latter a separate scientific, privacy and capacity workstream. Both can be explored with public data offline without changing the current product promise.

**Suggested sequence:** (1) benchmark/model/license provenance and result meaning; (2) #1/#3/#4/#7/#11 plus interactive public example and #10 API client; (3) #2 and one evidence adapter, with CFD where justified; (4) optional IGV and third-party file adapters; (5) research pilots only if they solve an observed user problem. Performance and maintenance evidence accompany each step.

Open council decisions:

- Which exact independent assay and guide set will be locked, and was it used in model/k selection?
- Is the central demonstrated use case better site ranking at fixed experimental budget, or a measurable usability benefit? What baseline workflow and success criterion will be fixed before evaluation?
- Which single experimental report format is most common among the intended first users?
- Who can grant public model/checkpoint redistribution and document the five-year hosting and maintenance commitment?
- Should intended-locus selection be required only for guide summaries, while pair scoring and possible on-target display remain fully available?
